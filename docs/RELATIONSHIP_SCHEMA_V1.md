# PSYWERX Relationship Schema v1.0

Relationship Schema v1.0 defines the canonical public representation of the
`Relationships` worksheets embedded in the eight standardized PSYWERX Driver
Ontology workbooks. These worksheets are the authoritative source for
structured, evidence-bearing Driver-to-Driver edges.

The public artifact uses this envelope:

```json
{
  "schemaVersion": "1.0",
  "relationships": []
}
```

## Canonical fields

| Canonical field | Spreadsheet header | JSON type | Requirement | Technical meaning | Normalization |
|---|---|---|---|---|---|
| id | Relationship ID | string | Required | Permanent identity of the relationship record. | Preserve the explicit source value exactly. Never regenerate it from row position or edge content. |
| sourceDriverId | Source Driver ID | string | Required | Stable ID of the Driver from which the directed edge originates. | Preserve exactly and require an exact match to one `data/drivers.json` ID. |
| sourceDriverName | Source Driver | string | Required | Canonical source Driver name recorded with the edge. | Trim surrounding whitespace, preserve source wording, and require exact equality with the name belonging to `sourceDriverId`. |
| targetDriverId | Target Driver ID | string | Required | Stable ID of the Driver at which the directed edge terminates. | Preserve exactly and require an exact match to one `data/drivers.json` ID. |
| targetDriverName | Target Driver | string | Required | Canonical target Driver name recorded with the edge. | Trim surrounding whitespace, preserve source wording, and require exact equality with the name belonging to `targetDriverId`. |
| relationshipType | Relationship Type | string | Required | Source-authored classification or characterization of the edge. | Trim surrounding whitespace and otherwise preserve source wording exactly. This field is not a Codebook-controlled vocabulary in Schema v1.0. |
| expectedDirection | Expected Direction | string | Required | Expected direction or form of the specific edge under its stated conditions. | Trim surrounding whitespace and require exact membership in Codebook term `CB-REL-EXPECTED-DIRECTION`. Direction belongs to the edge, not either Driver. |
| functionalForm | Functional Form | string | Required | Source description of the edge's functional form. | Trim surrounding whitespace and otherwise preserve source wording. |
| moderatorsConditions | Moderators / Conditions | string | Required | Conditions that qualify the relationship's direction, strength, or applicability. | Trim surrounding whitespace and otherwise preserve source wording. |
| timeLag | Time Lag | string | Required | Source description of the delay associated with the edge. | Trim surrounding whitespace and otherwise preserve source wording. Schema v1.0 does not reinterpret this as a Driver temporal field. |
| evidenceStrength | Evidence Strength | string | Required | Strength of support for this specific edge. | Trim surrounding whitespace and require exact membership in Codebook term `CB-REL-EVIDENCE-STRENGTH`. Do not infer it from Driver-level evidence. |
| evidenceNotes | Evidence Notes | string | Required | Source notes describing support, uncertainty, and limitations for the edge. | Trim surrounding whitespace and otherwise preserve source wording. |
| evidenceIds | Evidence IDs | array of strings | Required | Ordered references to source Evidence records supporting the relationship. | Split the source cell on semicolons, trim each ID, preserve source order, and reject empty or duplicate items. |
| source | Generated by importer | object | Required | Public provenance for the source relationship row. | Include only workbook filename, worksheet name, and one-based row number. Never expose a local filesystem path. |

Every relationship record contains every canonical JSON key. Relationship
Schema v1.0 requires all 13 source fields to be populated; `evidenceIds` must be
a non-empty array.

## Exact worksheet contract

The canonical source table is the `Relationships` worksheet, with its header in
row 4 and data beginning in row 5. The required headers, in order, are:

1. Relationship ID
2. Source Driver ID
3. Source Driver
4. Target Driver ID
5. Target Driver
6. Relationship Type
7. Expected Direction
8. Functional Form
9. Moderators / Conditions
10. Time Lag
11. Evidence Strength
12. Evidence Notes
13. Evidence IDs

Missing, reordered, renamed, or unexpected headers are errors. The eight
workbook copies must all satisfy this same contract.

## Identity and graph rules

- One structured record represents one directed evidence-bearing edge:
  `Source Driver → Target Driver`.
- From the Source Driver's perspective, the Target Driver is downstream. From
  the Target Driver's perspective, the Source Driver is upstream.
- The importer does not create separate `likely_upstream` and
  `likely_downstream` records for the same edge. Consumers derive those two
  perspectives from the direction of the one canonical relationship.
- Relationship IDs are explicit, permanent, and globally unique.
- Source and target Driver IDs must resolve exactly against
  `data/drivers.json`; aliases and fuzzy name matching are not used.
- Source and target names must exactly match the canonical names attached to
  their IDs.
- Self-relationships are prohibited.
- A directed `(sourceDriverId, targetDriverId)` pair may occur only once.
- Duplicate relationship records are prohibited even if assigned different
  IDs.
- Same-layer relationships are valid, and future cross-layer relationships are
  also valid when they are explicitly present in a canonical Relationships
  worksheet. Cross-layer edges are not synthesized from narrative text.

## Controlled and source-authored values

`expectedDirection` and `evidenceStrength` are controlled by the canonical
public Codebook. The importer obtains their allowed values from
`data/codebook.json` rather than duplicating a second vocabulary.

`relationshipType` is source-authored free text in Schema v1.0. The importer
preserves it exactly and reports an inventory, including capitalization-only or
obvious lexical variants, without normalizing or merging terms.

## Scope and source distinction

The structured `Relationships` worksheets are authoritative for public graph
edges. Driver narrative fields such as `likelyUpstreamInfluences`,
`likelyDownstreamInfluences`, and `typicalInteractionCandidates` remain useful
descriptive and retrieval metadata, but they are not canonical graph edges and
are never converted into relationships by this importer.

The current relationship set is intentionally conservative and non-exhaustive.
Absence of an edge does not establish absence of influence. Expected direction,
functional form, evidence grade, and qualifying conditions describe the
specific relationship record rather than a universal property of either
Driver.

## Determinism, provenance, and output safety

The importer validates all workbooks, Driver references, controlled values,
identity constraints, and graph constraints in memory before writing. It
atomically replaces `data/relationships.json` only when the complete build has
no errors.

Records are sorted deterministically by canonical source-workbook layer,
Relationship ID, source Driver ID, and target Driver ID. JSON is UTF-8 and
pretty-printed. Provenance contains only the source workbook filename,
worksheet name, and one-based row number.

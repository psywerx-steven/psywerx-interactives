## Plain-language architecture recommendation

Rates of forming or closing ties do not tell us which actors and ties exist. A network statistic describes a configuration; it is not an independently editable primitive. Put exact configuration in an optional **scenario-state substrate**, not a new Driver. Keep observed network data distinct from assumptions about the real network. Calculate RDS from explicit state/boundary/metric inputs.

Use a separate deterministic scenario delta for “move this fictional actor to this group.” That does not establish “group assignment causes friendship.” Keep scientific effects under existing AE04 Driver/Relationship targeting. This hybrid is a recommendation, not approved architecture, and does not cure every scientific target gap.

The isolated [proposal](../../../../experiments/network-state-vnext/ARCHITECTURE_PROPOSAL.md) compares Driver-only, new ontology-type and hybrid options. [NS01–NS12](../../../../experiments/network-state-vnext/GOVERNANCE_DECISIONS.md) are all **PENDING**: need for state, placement, naming, minimum schema, observation distinction, derivation bindings, AE interface, AE04 vocabulary, delta object, version/provenance, privacy, and compatibility/scale-up.

Nine fictional examples distinguish tie changes, node entry/exit, membership, boundary expansion, weight, access and seating opportunities. They recompute degree, density, local clustering, pair-disconnection fragmentation and degree-based centralization. They do not establish scientific effects, estimate latent networks, simulate diffusion or activate model/recommendation behavior.

# Layer Scale-Up V2 model routing

## Default route

Use **GPT-5.6 Sol High** for normal Layer execution: inventory interpretation, Family landscape synthesis, candidate triage, routine source extraction, standard retain/research-needed assessment, deduplication, structured artifact generation, tests, Git, and documentation.

Model routing is workflow guidance. Do not store provider or model names in scientific records or schemas. Every output remains subject to the same evidence, provenance, validation, governance, and activation boundaries regardless of route.

## Escalate to Astra XHigh

Escalate only a bounded question involving one or more of:

- an unresolved ontology or construct dispute;
- a difficult RDS causal-source question;
- an architecture or target-semantics issue;
- conflicting high-quality evidence that changes the exact proposition;
- high-consequence `REVIEW_READY` science; or
- a final small-set skeptical review when the expected decision value justifies it.

Record the candidate/issue IDs, exact unresolved question, evidence already reviewed, competing interpretations, consequence of error, and requested output. The escalation may recommend downgrade or blockage; it has no governance authority.

## Do not escalate routinely

Do not require Astra for inventories, formatting, coverage accounting, deduplication, routine source extraction, ordinary retain/research-needed decisions, test generation, Git, or documentation. Volume, deadline pressure, or a desire for higher candidate yield is not an escalation reason.

## Resolution

An escalation ends with one of: resolved within existing contracts, downgrade to research-needed, blocked for human ontology/architecture governance, or individual scientific decision for the human package. Preserve dissent, uncertainty, and source conflicts. Never implement ontology, architecture, production-science, or activation changes as part of model routing.
